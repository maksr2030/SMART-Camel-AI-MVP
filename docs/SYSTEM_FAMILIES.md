### ملاحظات معمارية

- يمكن أن ترتبط قدرة واحدة بأكثر من عائلة عند التكامل، لكن سجل F-ID يحتفظ بعائلة تشغيل أساسية واحدة لتجنب الازدواج.
- العائلات ليست حدوداً قانونية للملكية الفكرية؛ هي تصنيف هندسي وعرضي عام.
- حالات النضج تبقى على مستوى القدرة الفردية، لأن العائلة الواحدة قد تجمع Implemented وDemonstrated وSimulated وMock Integration وPlanned.
- لا تساوي العائلة النظامية تطبيقاً منفصلاً أو خدمة مستقلة في التسعير التجاري.

## English

### Purpose

This document organizes the 243 canonical capability records into **20 canonical system families** for architecture review and technical due diligence. A system family is an architectural grouping, not necessarily a separate product, and it does not imply that every member capability is production-deployed.

**Current result: 20 canonical system families.**

### Architectural notes

- A capability may participate in several integration contexts, while its F-ID keeps one primary operating family to prevent double counting.
- These families are architectural/public presentation categories, not legal IP boundaries.
- Maturity remains attached to each individual capability because one family can contain Implemented, Demonstrated, Simulated, Mock Integration and Planned records.
- A system family does not automatically equal a separately priced application or commercial SKU.
